Working with agents 101

Zero-assumed-knowledge on-ramp. An "agent" is just an AI model that can use tools in a loop — read files, run commands, edit code — until a task is done. Everything below builds on that one idea.

Start here

  1. Get the mental model — read Building Effective Agents (Anthropic). Short, no hype, explains workflows vs. agents and why simple beats clever
  2. Install a coding agent — follow Setup: pick a client, install it, get an account that works. Claude Code is our default. Cursor works too (docs)
  3. First session — open your repo, ask it to explain something you already understand, and judge the answer. Trust is earned per-task, not granted
  4. Then switch to how your team works — the Guide: the gate, the ticket lifecycle, what counts as proof

Wiring your own tools in

MCP is how an agent reaches things that are not files — your editor, your build system, a database, this hub. Two starting points:

  • MCP: getting started — what a server is and how a client finds it. Read this before wiring anything
  • Reference MCP servers — a catalogue of existing ones. Check here before writing your own
This hub is itself an MCP server. functions/mcp/ exposes meetings, action items, the agent-ready queue and the file store, so an agent working in your repo can read the hub instead of a person relaying it. See the README under Connecting an agent.

Replace this section with the servers your team actually pins — and pin a version. Riding @latest on something that can edit your project is how a quiet morning ends.
